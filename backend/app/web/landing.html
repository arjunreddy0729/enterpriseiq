EnterpriseIQ

A permission-aware RAG system. It answers questions from company documents with a citation for every claim, declines when the documents don't contain the answer, and never shows anyone a document they aren't allowed to read.

The company, "Northwind Systems", and all 22 of its documents are fictional.

Try it in four steps

  1. Open the API console, click Authorize, and log in as Marcus: his email as the username, the password above. Leave the client fields empty.
  2. Open POST /api/v1/query, click Try it out, then Execute. It asks "What are the bonus targets by level?" and answers with a citation to the HR compensation policy.
  3. Click Authorize, log out, and log in as Priya. Run the same question. She is an engineer, so the HR policy is filtered out inside the database query and the system declines without ever sending HR text to the model.
  4. Log in as the admin and open GET /api/v1/admin/audit/documents/{document_id} (ids come from GET /api/v1/admin/documents) to see who retrieved a document.

POST /api/v1/search shows the retrieved passages without calling the model at all.

About this demo

Written answers use Claude and are capped at a small daily budget; when it runs out, search keeps working and answers resume at 00:00 UTC. Requests are rate-limited per visitor. Changing permissions is turned off here because everyone shares the admin login; the source code shows how to run it locally, where revocation works.

Questions are stored in the request log, which is how the audit trail works. Other visitors can't see their text, but please don't type anything personal.
